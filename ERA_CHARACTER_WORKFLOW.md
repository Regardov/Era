## 3. Что находится в библиотеке

- `ERA_BASE_COMPATIBLE`: один `Archer_Rig` с 54 костями и 13 mesh-компонентов: шея, elf-голова, туника как корпусная оболочка, руки в рукавах, перчатки, наручи, ноги в штанах и ботинки.
- `ERA_OPTIONAL_COMPONENTS`: наплечники, коленные элементы, грудной слой, нижние панели, шарф, пояс/подсумки и нагрудные ремни.
- `ERA_ARCHER_ONLY_COMPONENTS`: причёска эльфа, капюшон, заострённый плащ, лук/тетива, колчан/его крепление и стрелы. Не включены в базу автоматически.
- `ERA_REFERENCE_ARCHER`: отдельная скрытая контрольная сборка исходных 23 мешей. Объекты помечены `era_reference=True`; helpers отказываются редактировать их.
- 26 неизменённых Actions и 19 материалов отмечены как Blender Assets. Вся библиотечная сцена содержит также контрольный экземпляр — её нельзя целиком экспортировать как нового персонажа.

**Ограничение базы:** это разбор существующей одетой модели, а не готовое голое тело. Без наружных панелей видны незаполненная область таза и другие места, закрытые исходной одеждой. Голова рассчитана на волосы/головной убор. Для открытого тела, полной причёски или другой анатомии требуется отдельное моделирование по новому заданию; не выдавать пробелы за законченную анатомию.

## 4. Загрузка в новый рабочий файл

Можно зарегистрировать папку `ArtSource/CharacterFactory` как Asset Library в Blender Preferences вручную. Автоматическое изменение пользовательских Preferences не требуется. Доступен и обычный File → Append → `ERA_CharacterLibrary.blend` → Collection → `ERA_BASE_COMPATIBLE`.

Для воспроизводимой загрузки запустить этот код в **новом пустом файле** через Blender Text Editor или свой CLI-скрипт. `factory` — абсолютный путь к каталогу набора на текущем компьютере:

```python
import bpy, sys
from pathlib import Path
factory = Path(r"<ERA checkout>/ArtSource/CharacterFactory")
sys.path.insert(0, str(factory))
from era_character_factory.components import append_template, append_component
collection, rig, meshes = append_template(factory / "ERA_CharacterLibrary.blend")
# Затем Save As в новый файл персонажа; не сохранять поверх библиотеки/лучника.
```

Если файл уже содержит `Archer_Rig`, Blender добавит суффикс `.001`. Это не совместимое имя для текущих Generic paths. Начать с пустого файла либо изолировать рабочую копию; не переименовывать эталон и не менять глобальные клипы ради обхода коллизии.

Для нужного необязательного элемента:

```python
shoulder = append_component(factory / "ERA_CharacterLibrary.blend",
                            "CF_ShoulderArmor_L", rig, collection)
meshes.append(shoulder)
```

Функция сохраняет веса и привязывает компонент к рабочему ригу. При прямом Append отдельного Object обязательно проверить, к какому Armature указывает modifier: Blender может принести дополнительный dependency rig. Не оставлять два конкурирующих скелета на одном персонаже.

## 5. Пропорции и крупные формы

Отсоединить активный Action рабочей копии, отключить NLA, работать в rest-геометрии. Сначала менять только необходимые крупные массы; все связанные слои передавать одной операции:

```python
from era_character_factory.proportions import scale_region
rig.animation_data_clear()
scale_region(rig, meshes, center=(0, 0, 1.09), radius=(.24, .28, .23),
             scale=(.91, .97, 1), change_rest=False)
```

Это общий плавный геометрический field вокруг указанной области: коэффициент .91 не означает уменьшение всех сечений на ровно 9%. Rest pose сохраняется. Не забыть включить пояс/плащ/ремни и проверить привязки. Требуется повторный просмотр деформаций, даже если schema совместима.

`change_rest=True` также меняет rest-координаты костей, помечает `era_requires_rebake=True`, блокирует прямое назначение старого Action и animated export. Это инструмент изменения конструкции; автоматического retarget/rebake в наборе нет. Для значительного изменения длины конечностей запланировать отдельную адаптацию анимаций.

`scale_character()` даёт равномерный масштаб всей рабочей ветки без изменения локальных единиц клипов. Не выполнять Apply Scale на keyed Armature вслепую. FBX-экспорт набора ожидает единичный scale: игровой рост задаётся явно при последующей Unity-интеграции.

Сделать blockout и одинаковые front/side/back контрольные виды. Не переходить к аксессуарам, пока пропорции и силуэт не соответствуют новому референсу.

## 6. Одежда и палитра

- `geometry.faceted_loft()` — явные многогранные кольца для неодинаковых сечений.
- `geometry.clothing_panel()` — закрытая тонкая выпуклая плоская панель. Для сложной/неплоской ткани задавать свою геометрию или несколько loft-секций.
- `geometry.surface_ribbon()` — ремень с проекцией обеих кромок на фронтальную опорную поверхность; остановится, если под краем нет поверхности.
- `geometry.triangulate_faces()` — фиксированная диагональ только выбранных граней.
- `components.attach_rigid()` — однокостное крепление небольшого жёсткого элемента. Не использовать для длинной гибкой ткани через несколько суставов.
- `materials.material_from_hex()` — новый материал с преобразованием sRGB → linear.
- `materials.replace_material()` — смена материала в рабочей копии. Не редактировать shared material эталона.
- `materials.compact_slots()` — удаление неиспользуемых слотов с сохранением материала каждой грани.

Геометрия должна работать и в clay-виде. Мелкий декор и фактурная раскраска добавляются после силуэта и layering. Для новой расы заменить elf-голову; не пытаться получить человеческий череп равномерным уменьшением ушей вместе со всем лицом.

## 7. Проверки перед экспортом

```python
import json
from era_character_factory.rig import compatibility
from era_character_factory.qa import mesh_report, surface_contacts
from era_character_factory.render import review_views
schema = json.loads((factory / "rig-schema.json").read_text(encoding="utf8"))
print(compatibility(rig, schema))
print(mesh_report(rig, meshes))
review_views(rig, meshes, "<working output>/Review", "character")
review_views(rig, meshes, "<working output>/Review", "character", views=("front",), clay=True)
```

Проверить отрицательные масштабы, нулевые грани, веса, силуэт, стопы, подмышки, кисти, края одежды, оружие. Открытые края отдельных лицевых островов не исправлять общей сваркой всего персонажа.

`surface_contacts()` получает **явные пары объектов** в текущей evaluated-позе. Он сообщает пересекающиеся грани, а не точную глубину/объём. Полное вложение поверхностей, касание и движение между выборками могут остаться незамеченными. Допустимые конструктивные контакты перечислять с причиной, а не скрывать все пересечения. Проверить несколько кадров Idle/Walk/Run/Cast и действия с соответствующим оружием, затем реальную игру при интеграции.

## 8. Переиспользование анимаций

```python
from era_character_factory.rig import load_actions, bind_action
assert compatibility(rig, schema)["compatible"]
actions = load_actions(factory / "ERA_CharacterLibrary.blend")
bind_action(rig, actions["Archer_Walk"])
bpy.context.scene.frame_set(8)
```

Банк неизменён. Чтобы править движение нового героя, сделать отдельную копию Action и дать новое имя; никогда не переписывать общий банк. `Archer_Bow*`, тетива, сокеты и события стрельбы специфичны для лучника: наличие этих кривых на совместимом риге не делает монаха стрелком. Для отсутствующей экипировки extension bones могут оставаться без мешей.

## 9. Unity-экспорт и последующая интеграция

```python
from era_character_factory.export import export_unity
export_unity(rig, meshes, "<ERA checkout>/Artifacts/<Character>/<Character>.fbx",
             schema, animations=True)
```

Экспортирует только выбранные rig + meshes, а не reference/library collection. Animated export запрещён при изменённом rest, неподходящем имени rig, активном NLA или постороннем Action bank. Метод намеренно не пишет в текущий `Assets`.

При отдельном задании на интеграцию создать новый asset/prefab с собственными .meta, сохранить корневые gameplay-компоненты. Generic / CreateFromThisModel / Root=`Root`, без optimized GameObjects; применить scale и отключить Root Motion. Проверить curve paths и Avatar. Использовать существующие `.anim` напрямую, если skeleton/path contract сохранён; убедиться, что клипы являются runtime AnimationClip (class 74), а не editor-only PreviewAnimationClip.

**Не запускать `ArcherAnimationImporter.Prepare()` для произвольного нового героя:** он специально мигрирует существующий Ember и требует его оружие/сокеты. Нужна осмысленная привязка существующего контроллера/override и соответствующей логики класса. Унаследовать только подходящие layers/masks и клипы. Проверить реальный экземпляр: стояние, движение, действия, переходы, события, деформации и других персонажей. Изолированная Editor-проверка набора этого не заменяет.

Проверка включает сохранение SHA256 оригинала, точное разбиение исходных граней/материалов на компоненты, веса, изменение пропорций/материала/одежды, положительный тест пересечений, отказ редактировать reference, отказ переиспользовать Action после rest edit, выборку 26 Actions и отдельный Unity import/binding test.
